Dictionaries — Key-Value Pairs
The most powerful way to store related data

What is a Dictionary?

A list stores items by position (index). A dictionary stores items by name (key). Instead of saying "give me item 0", you say "give me the 'name' value".

📒 Analogy: Think of a real dictionary or contact book. You do not look up a word by its page number — you look it up by its NAME. Each word (key) has a meaning (value). Python dictionaries work exactly the same way!

Creating a Dictionary

Use curly braces {}. Each entry is a key: value pair separated by commas.

dict_intro.py
# Create a dictionary with { }
student = {
    "name"  : "Riya Sharma",
    "age"   : 20,
    "course": "AI Engineering",
    "gpa"   : 8.7
}

# Access values by KEY name
print(student["name"])    # Riya Sharma
print(student["age"])     # 20
print(student["gpa"])     # 8.7

# Update a value
student["age"] = 21
print(student["age"])     # 21

# Add a new key-value pair
student["city"] = "Hyderabad"
print(student)
▶ Output
Riya Sharma 20 8.7 21 {'name': 'Riya Sharma', 'age': 21, 'course': 'AI Engineering', 'gpa': 8.7, 'city': 'Hyderabad'}

Dictionary Methods & Looping
Built-in tools to work with dictionaries

Essential Dictionary Methods

dict_methods.py
student = {"name":"Riya", "age":20, "gpa":8.5}

# .keys()   — all the keys
print(student.keys())      # dict_keys(['name','age','gpa'])

# .values() — all the values
print(student.values())    # dict_values(['Riya', 20, 8.5])

# .items()  — all key-value pairs
print(student.items())     # dict_items([('name','Riya')...])

# .get() — safe access (no error if key missing)
print(student.get("name"))          # Riya
print(student.get("city", "Unknown")) # Unknown

# Check if key exists
print("name" in student)   # True
print("city" in student)   # False

# Delete a key
del student["gpa"]
print(student)
💡 Always use .get() for safe access! If you use student["city"] and "city" does not exist, Python throws a KeyError and crashes. student.get("city", "Unknown") safely returns "Unknown" instead!

Looping through a dictionary

dict_loop.py
student = {"name":"Riya", "age":20, "city":"Hyderabad"}

# Loop through keys (default)
for key in student:
    print(key, "→", student[key])

# Loop through key-value pairs together
for key, value in student.items():
    print(f"{key}: {value}")
▶ Output (items loop)
name: Riya age: 20 city: Hyderabad

Tuples — Immutable Lists
Lists that cannot be changed after creation

What is a Tuple?

A tuple is exactly like a list — except you cannot change it after it is created. It is immutable (unchangeable). You create it with () instead of [].

🏛️ Analogy: Think of the days of the week — Monday, Tuesday, Wednesday... They are always in that order and never change. A tuple is perfect for data that should stay fixed forever, like coordinates, RGB colors, or days of the week!

Tuple syntax and accessing

tuples.py
# Create with ( ) — parentheses
colors      = ("red", "green", "blue")
coordinates = (17.385, 78.486)   # Hyderabad lat/lon
rgb         = (255, 165, 0)         # orange color

# Access by index — same as lists
print(colors[0])          # red
print(colors[-1])         # blue
print(len(colors))        # 3

# Unpack tuple into variables
lat, lon = coordinates
print(f"Latitude: {lat}, Longitude: {lon}")

# Loop through tuple — same as list
for color in colors:
    print(color)

📋 List [ ] — mutable

fruits = ["apple", "mango"]
fruits[0] = "grape"  # ✅ OK
fruits.append("kiwi")  # ✅ OK
# Use for: collections that change

🔒 Tuple ( ) — immutable

point = (10, 20)
point[0] = 99   # ❌ ERROR!
# Use for: fixed data like
# coordinates, settings, days

When to use a Tuple?

Use tuples when you want to make sure the data cannot be accidentally changed. Common uses:

tuple_uses.py
# Fixed configuration — should never change
DB_CONFIG = ("localhost", 5432, "mydb")

# Days of the week — fixed order
DAYS = ("Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun")
print("Weekdays:", DAYS[:5])

# Functions returning multiple values use tuples!
def min_max(numbers):
    return min(numbers), max(numbers)   # returns a tuple

low, high = min_max([5, 2, 9, 1, 7])
print(f"Min: {low}, Max: {high}")

Reading Files
Loading real data from your computer

Why File Handling?

Every real program works with files — reading CSV data, loading configuration, saving user data. Python makes it super easy with the built-in open() function.

📚 Analogy: Think of a file like a book. Before you can read it, you open it. After you are done, you close it. Python's open() opens the file, you read it, and you close it when done — just like a real book!

How to read a file

# Read entire file as one big string file = open("notes.txt", "r") # "r" = read mode content = file.read() print(content) file.close() # always close!
# Read one line at a time file = open("notes.txt", "r") first_line = file.readline() print(first_line) file.close()
# Read all lines into a list file = open("notes.txt", "r") lines = file.readlines() # returns a list for line in lines: print(line.strip()) # .strip() removes \n file.close()
📌 The "r" mode means READ. File modes:
"r" — read (file must exist)
"w" — write (creates new / overwrites)
"a" — append (adds to end of file)
"r+"— read and write
✏️
Writing to Files
Saving data permanently to disk

Writing and Appending

write_files.py
# "w" mode — write (WARNING: overwrites existing content!)
file = open("notes.txt", "w")
file.write("Hello from Python!\n")
file.write("This is line 2.\n")
file.close()

# "a" mode — append (adds to END, keeps existing content)
file = open("notes.txt", "a")
file.write("This line was added later.\n")
file.close()

# Read it back to verify
file = open("notes.txt", "r")
print(file.read())
file.close()
⚠️ "w" mode is destructive! If the file already exists, "w" completely erases everything in it before writing. Use "a" (append) when you want to ADD to existing content!

The with Statement — The Right Way
Automatically closes files — even if an error happens

Why use with?

When using open() manually, you must always remember to call .close(). If your program crashes before reaching close(), the file stays open — causing problems. The with statement handles closing automatically, every time.

🚪 Analogy: Imagine a room with a door. Without with, you have to remember to close the door yourself — and might forget. With with, the door closes automatically the moment you step out, no matter what!

with vs without — always prefer with!

❌ Old way — risky

f = open("data.txt","r")
text = f.read()
# what if error here?
f.close()  # might never run!

✅ with — always safe

with open("data.txt","r") as f:
    text = f.read()
# file auto-closed here!

with statement — full examples

with_statement.py
# Writing with 'with'
with open("students.txt", "w") as f:
    f.write("Riya Sharma\n")
    f.write("Ali Khan\n")
    f.write("Priya Patel\n")
# file is automatically closed here

# Reading with 'with'
with open("students.txt", "r") as f:
    for line in f:          # loop through each line
        print(line.strip())

# Writing data from a list
students = ["Riya", "Ali", "Priya"]

with open("names.txt", "w") as f:
    for name in students:
        f.write(name + "\n")
