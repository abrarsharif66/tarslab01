ANN vs RNN — Why Sequence Matters
Language is an ordered stream, not a bag of independent inputs

The problem with a normal neural net (ANN)

A regular feed-forward neural network (an ANN) takes a fixed-size input, processes it all at once, and treats every input as independent. That is fine for a photo of a cat — all the pixels arrive together.

But language is a sequence. "The dog bit the man" and "The man bit the dog" use the exact same words — only the order changes the meaning. An ANN that ignores order would see these as identical. We also rarely know how long a sentence will be, so a fixed-size input is awkward.

📖 Analogy: Reading a sentence is not like glancing at a photo. You read word by word, and you remember what came before to make sense of the next word. By the time you reach "it" in "The trophy didn't fit in the suitcase because it was too big", your brain still holds "trophy" and "suitcase" in memory to figure out what "it" means.

RNN = a neural net with memory

A Recurrent Neural Network (RNN) adds a small piece of memory called the hidden state. It reads the sequence one item at a time and passes its memory forward from each step to the next. So when it reads word 5, it still "remembers" a summary of words 1 to 4.

The word recurrent just means the network feeds part of its own output back into itself for the next step — like a loop.

🧱 ANN (Feed-Forward)

  • Fixed-size input, all at once
  • Inputs treated as independent
  • No memory of order
  • Great for images, tabular data
  • Same input → same output, always

🔁 RNN (Recurrent)

  • Reads a sequence step by step
  • Carries a hidden state (memory)
  • Order & context affect the result
  • Great for text, speech, time series
  • Output depends on what came before
💡 Why it matters: Almost everything in language — grammar, meaning, "who does what to whom" — depends on order. RNNs were the first popular deep-learning tool that respected that, and they paved the road to today's Transformers.
⚙️
How an RNN Works (Plainly)
One step at a time, carrying memory forward

The core idea: combine "new word" + "old memory"

At every time step (one per word), the RNN does the same little recipe: it takes the new word and the previous hidden state (its memory so far), mixes them together, and produces a new hidden state — an updated memory. It can also output a prediction at each step.

🗣️ Analogy: Imagine a person summarizing a story as they hear it. After each new sentence they update their one-line summary: "old summary + new sentence → new summary." The hidden state is that running summary.

"Unrolling" through time

It is the same network reused at each step — but to picture it, we "unroll" the loop into a chain, one copy per word. The memory arrow flows left to right.

word₁ word₂ word₃ word₄ │ │ │ │ ▼ ▼ ▼ ▼ [ RNN ] ─h₁─▶ [ RNN ] ─h₂─▶ [ RNN ] ─h₃─▶ [ RNN ] ─▶ output ▲ h₀ (empty memory) h = hidden state (memory)

Notice each box passes its hidden state h to the next box. By the last step, the final hidden state has "seen" the whole sentence.

The four-step loop

Take the next wordConvert the word into a vector (an embedding) and feed it in.
Mix with memoryCombine this word with the previous hidden state to make a new hidden state.
Optionally outputProduce a prediction for this step (e.g. the next word, or a sentiment).
Pass memory forwardSend the new hidden state to the next time step, then repeat for the next word.

Training: Backpropagation Through Time (BPTT)

How does it learn? After the RNN makes a prediction, we measure the error and send "blame" backward to adjust the weights — just like any neural net. Because the network was unrolled across many time steps, the blame must travel back through every step. That is why it is called backpropagation through time.

🎯 Intuition (no calculus needed): Think of a relay race run badly. To fix it, you trace the mistake back through every runner who touched the baton, nudging each one to do a little better next time. BPTT nudges the network at every time step.
⚠️
Problems with Plain RNNs
Why simple RNNs struggle with long sentences

The long-term memory problem

When the blame travels back through many time steps during training, it gets multiplied over and over. Two bad things can happen:

  • Vanishing gradients: the signal shrinks toward zero, so the network barely learns from words far in the past — it effectively forgets long-range context.
  • Exploding gradients: the signal blows up to huge numbers, making training unstable.
📣 Analogy: Plain RNNs are like the game "telephone" — whispering a message down a long line of people. By the time it reaches the end, the original message is garbled or lost. The longer the line (the longer the sentence), the worse it gets.
⚠️ Two real headaches:
1. Forgetting: A plain RNN reading "I grew up in France ... so I speak fluent ____" may have forgotten "France" by the time it needs to predict "French".
2. Slow training: Because it must process words strictly one after another, it cannot easily use parallel hardware — long sequences are slow to train.
💡 Why it matters: These limits are exactly what the next architectures — LSTM, GRU, and later Transformers — were invented to fix. Understanding the problem makes the solutions click.
🧮
LSTM — Long Short-Term Memory
A smarter memory that decides what to keep and what to forget

The fix: a protected memory + gates

An LSTM is an upgraded RNN cell. Alongside the hidden state, it adds a cell state — a kind of conveyor belt that carries information straight down the sequence with very little change, so important facts survive over long distances.

To control what flows on and off that belt, the LSTM uses three gates. A gate is just a tiny switch (a value between 0 = "block" and 1 = "let through") that the network learns to operate.

📔 Analogy: Picture a smart notebook you carry through a story. At each new sentence you (1) erase notes that no longer matter, (2) write down important new facts, and (3) decide which notes to read aloud right now. Those three actions are exactly the three LSTM gates.

The 3 gates of an LSTM

GateJobNotebook analogy
Forget gateDecides what to drop from the cell stateerase old, no-longer-relevant notes
Input gateDecides what new info to add to the cell statewrite down important new facts
Output gateDecides what to expose as this step's hidden statechoose which notes to read aloud now

Putting it together

┌──────── cell state (the conveyor belt) ────────▶ │ ▲ ▲ │ forget input (update) output gate gate gate │ │ │ └─────┴──────────────────────────┴──▶ hidden state out

The forget and input gates rewrite the conveyor belt; the output gate reads from it to produce what the next layer sees.

💡 Why it matters: Because the cell state can carry information almost unchanged across many steps, LSTMs largely solve the long-term memory problem. They can remember "France" long enough to later predict "French" — something a plain RNN struggles to do.
🔀
GRU & Bidirectional RNNs
A lighter cousin of the LSTM, and reading both directions

GRU — Gated Recurrent Unit

A GRU is a simpler, faster version of the LSTM. It merges ideas together and uses only 2 gates instead of 3, and it drops the separate cell state. Fewer parts means fewer parameters, quicker training, and often very similar accuracy.

🚗 Analogy: If an LSTM is a full SUV with every feature, a GRU is a nimble compact car — lighter and quicker, and for most everyday trips it gets you there just as well.

🧮 LSTM

  • 3 gates: forget, input, output
  • Has a separate cell state
  • More parameters, a bit slower
  • Strong on very long, complex sequences

⚡ GRU

  • 2 gates: update, reset
  • No separate cell state
  • Fewer parameters, faster to train
  • Great default for smaller data / quick models
GRU GateWhat it does
Update gateDecides how much old memory to keep vs. how much new info to add (like forget + input merged)
Reset gateDecides how much past memory to ignore when forming the new candidate memory

Bidirectional RNN — read forwards AND backwards

A normal RNN only sees the past. But sometimes the meaning of a word depends on what comes after it. A bidirectional RNN runs two passes — one left-to-right and one right-to-left — and combines them, so every word is understood with full context from both sides.

🔍 Analogy: In "He went to the bank to fish", you only know "bank" means a riverbank once you read "to fish" at the end. Reading the sentence both ways gives you that fuller picture.
🎯 When to pick which: Reach for a GRU when you want speed or have limited data; an LSTM for long, complex dependencies. Add bidirectional when the whole sequence is available at once (e.g. classifying a finished sentence) — but not for live, real-time prediction where the future isn't known yet.
🧩
Embedding Layers in Keras
Turning word IDs into trainable meaning-vectors

What an Embedding layer does

Neural networks only eat numbers. After tokenizing, each word becomes an integer ID (e.g. "movie" → 42). But an ID like 42 carries no meaning by itself. An Embedding layer is a lookup table that maps each ID to a small dense vector — and those vectors are trainable, so the model learns useful word meanings as it trains.

📇 Analogy: Think of the Embedding layer as a contact list. The token ID is a phone number (just a label); the embedding vector is the rich profile behind it. During training the model keeps editing each profile until similar words end up with similar vectors.
💡 Connects to Day 5: This is the same idea as Word2Vec embeddings — but instead of training them separately, the Embedding layer learns them inside your model, tuned for your specific task.

Step 1 — Tokenize & pad the text

Turn raw sentences into integer sequences, then pad them so every sequence is the same length (networks like fixed-size batches).

prep.py
from tensorflow.keras.preprocessing.text import Tokenizer
from tensorflow.keras.preprocessing.sequence import pad_sequences

texts = ["great movie loved it", "boring and too long"]

# Map each word to an integer ID
tok = Tokenizer(num_words=10000)
tok.fit_on_texts(texts)
seqs = tok.texts_to_sequences(texts)

# Make every sequence length 20 (pad/truncate)
X = pad_sequences(seqs, maxlen=20)
print(X.shape)   # (2, 20)

Step 2 — Build the classifier: Embedding → LSTM → Dense

A classic text classifier: the Embedding layer turns IDs into vectors, the LSTM reads the sequence and summarizes it, and a Dense layer makes the final prediction.

model.py
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Embedding, LSTM, Dense

model = Sequential([
    # IDs -> dense vectors (vocab=10000, vector size=64)
    Embedding(input_dim=10000, output_dim=64, input_length=20),
    # Read the sequence, keep 32 memory units
    LSTM(32),
    # Final yes/no prediction (positive vs negative)
    Dense(1, activation="sigmoid")
])

model.compile(optimizer="adam",
              loss="binary_crossentropy",
              metrics=["accuracy"])

model.summary()
▶ model.summary() (simplified)

🎯 Notice: The Embedding layer holds most of the parameters (10000 words × 64 numbers = 640,000). Swap LSTM for GRU, or wrap it in Bidirectional(LSTM(32)), and the rest of the model stays exactly the same.
